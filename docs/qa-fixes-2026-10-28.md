# Rättningar av Trädgårdsplanerarens Expoapp

F01–F08 är rättade och verifierade den 28 oktober 2026. Telefonpaketet och rättningarna levereras tillsammans med regressionstesterna. Mobilkod och serverkod behöver följa med tillsammans vid en framtida produktionsrelease; sådan aktivering ingår inte i denna leverans.

## Underlag och bevarat arbete

Utgångspunkten är den granskade arbetskopian `tradgardsrytmen-phone-test`, gren `task/planner-phone-test`, commit `7082264818967d7fb969f5b2a0500cd8ac3a33d7`, inklusive dess befintliga lokala ändringar. Samtliga kontrollsummor i felsökningens `source-manifest.json` matchade före arbetet. Även `working-tree-status.txt`, `preexisting-mobile-changes.patch` och PDF-rapporten kontrollerades.

Vid rättningens slutkontroll var originalkopians 340 kontrollerade filer oförändrade, inklusive telefonprovets databas och inloggningsuppgifter. Telefonpaketet och F01–F08 checkas in i separata commits så att tidigare arbete kan skiljas från rättningarna. Kontrollsummor och ursprunglig rättningspatch finns i det lokalt bevarade evidenspaketet.

F01-granskningen fångade dessutom ett race vid dubbel manuell avstämning. Avstämning och sparning delar nu samma pågående operation, så en sen avstämning inte kan radera nästa sparning. Det äldre flödet för klarmarkering av uppgifter fick också slutliga avslagskvitton, så att den gemensamma klientändringen inte inför en låsning vid nätfel följt av versionskonflikt.

## Slutlig verifiering

| Kontroll | Resultat |
| --- | --- |
| Mobiltester | 95 av 95 godkända, jämfört med baslinjens 72 |
| Django | 114 av 114 godkända, inga överhoppade |
| Integration | 2 av 2 sviter godkända, inklusive flera scenarier med riktig Django och återställd sparjournal |
| Typkontroll och lint | Godkända |
| Expo export | iOS, Android och webb godkända |
| Användarflöden | Alla fem huvudvyer, utkast, rådgranskning, verklig konflikt, inmatning, beräkning, sparning/återläsning och in-/utloggning kontrollerade i webbpreview |
| Originalkontroll | 340 kontrollsummor oförändrade |

Django-körningen omfattar `mobile_workspace`, `p2_api`, `care_lifecycle`, `phone_test_server`, `jobs`, `job_operations` och `pwa`. Ett första bredare prov med SQLite i minnet gav ett låsfel i det befintliga tvåtrådstestet för jobboperatörer och hoppade över fyra samtidighetstest. Slutkörningen använder en separat SQLite-fil, där samtliga 114 tester kördes och godkändes. Båda loggarna finns kvar.

Testservern använde en ny syntetisk databas i denna arbetskopia. AI, push och utgående servertransporter var avstängda. Integrationstesterna använde separata temporära databaser och nätspärrar. De tillfälliga servrarna är stoppade. Databaser och inloggningsuppgifter ingår inte i evidenspaketet.

## Underlag för fortsatt arbete

Loggar, skärmbilder, kontrollsummor, webbresultat och rättningspatch bevaras i det lokala evidenspaketet utanför versionshanteringen. Regressionstesterna ligger i projektets vanliga testmappar. `npm run test:integration` inkluderar nu även den nya workspace-proben och använder `python3` eller den uttryckligen angivna miljövariabeln `PYTHON`.

För återkörning från mobilmappen används `npm test`, `npm run typecheck`, `npm run lint`, `npm run test:integration` och `npm run export`. Pythonmiljön behöver projektets requirements. Serverpaketet kan köras med `config.p3_sqlite_test_settings` och en separat fil angiven i `P3_SQLITE_TEST_PATH`, som i GitHub Checks. Telefonprovet använder i stället `config.phone_test_settings`, som blockerar utgående servertransporter. Den nya workspace-integrationen blockerar själv utgående Pythonanslutningar och skapar en tillfällig databas.

Fysisk iPhone/Android, native-tangentbord och layout, verklig pushleverans, bakgrundsläge och faktisk appavslutning är fortfarande inte verifierade. F08-resultatet gäller fördröjda skrivningar och navigation inom samma appkörning. Inga kända hinder återstår för de automatiskt verifierade F01–F08-scenarierna.
